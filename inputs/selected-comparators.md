# Selected comparator set for Repo Onboarding Snapshot

This file is the clean comparison set to use.
Treat A-D as direct comparators.
Treat E as a guardrail, not a direct substitute.

## A. Decision-Grade Repository Audit | 48-Hour Technical Due Diligence Report
Why selected:
- closest shape to our offer: one repo, fast turnaround, written report
- validates that repository orientation and decision support are sellable
Keep:
- narrow scope
- fast delivery
- strong written output
Do not copy:
- AWS-heavy framing
- executive due diligence tone
- live debrief in base package

## B. A Senior-Level Codebase Audit & Stability Assessment
Why selected:
- directly names inherited legacy code and onboarding new developers
- useful upper anchor for what “broad audit” buyers already pay for
Keep:
- manual-review credibility
- inherited-code and onboarding trigger moments
Do not copy:
- full-spectrum audit claims
- broad business-alignment language
- consultative sprawl

## C. A professional backend code review and architecture audit
Why selected:
- clear mid-market report product
- shows how buyers accept a written technical report with recommendations
Keep:
- structured report framing
- clear risk categories
Do not copy:
- backend-only framing if our product is repo-onboarding first
- heavy security/performance promises

## D. A senior-level React code audit with clear fixes and priorities
Why selected:
- demonstrates the power of specificity
- concrete issue-count framing reduces buyer uncertainty
Keep:
- concrete deliverable framing
- prioritized outputs
Do not copy:
- framework-specific narrowing unless we intentionally launch a verticalized variant later
- bug-finding as the hero promise

## E. PHP Laravel Developer for Legacy Code Modernization
Why selected:
- not a direct comparator
- useful anti-pattern showing how audits turn into expensive custom implementation engagements
Keep:
- nothing from the base scope
Use only as a warning:
- do not bundle upgrades, refactors, migrations, AI features, or support into the core product

## Final recommendation
Position Repo Onboarding Snapshot as:
- narrower than a codebase audit
- more concrete than a consultation
- faster and cheaper than a full stability assessment
- most useful right after code handoff, re-entry into an old repo, or the first week on a new inherited system
